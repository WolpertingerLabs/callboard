# Native Codex agent tracking (#410)

## Design
- Preserve native child UUID and verified parent/thread-spawn identity in bounded metadata reads; never infer identity from inherited `session_id` or overwrite explicit Callboard parentage.
- Discover native descendants through the existing session provider, exposing additive lineage and read-only management metadata in list/detail/tree surfaces. Bound filesystem work and guard cycles.
- Separate child-local lifecycle evidence from copied fork history. Missing registry entries and stale logs mean unknown, not completed; report terminal states only from supported local events.
- Inspect installed exec SDK/CLI transport. Guard native-child send/resume/stop at entry points and the low-level executor before mutation/callback registration when independent controls are unavailable. Keep spawning available and explain parent-mediated control.
- Audit inherited parent-bound MCP identity; isolate identity-sensitive operations where defensible and explicitly record residual transport limitations.

## Transport evidence and explicit limitations
- Installed `@openai/codex-sdk` 0.153.4 (`dist/index.js`) invokes `spawn(executablePath, [exec, ..., resume, threadId], { signal })`. `resumeThread` launches a new exec invocation; abort controls that invocation, not an existing child of another exec. `codex-cli 0.153.4` exec help exposes no individual child interrupt/send endpoint. No app-server migration or process manipulation was performed.
- Read-only inspection of the supplied three rollouts shows the first `session_meta.id` is child-local while `session_id` remains root-local. The next metadata line is inherited root history. `subagent_history_start_ordinal` values 9/10/11 point exactly to the first local record. Timestamps on copied events were rewritten to child creation time, so timestamp filtering is unsafe. Replay uses the ordinal, never the copied lifecycle. Missing boundaries deliberately yield unknown/empty child transcript.
- Current native lifecycle is evidence, not a process monitor: active means local event activity within 30 seconds; stale activity/restarts cannot prove liveness and return unknown. `task_complete` is last-turn completion, not permanent thread closure. Completed children remain read-only because exec provides no ownership-release evidence. Error means an error event was observed, not proof that the child process exited.
- IO limits: metadata fallback reads at most 1 MiB; lifecycle replay at most 4 MiB (larger logs return unknown); dated-directory discovery has a 20,000-entry work budget, filesystem iterator order (only visited results are sorted by mtime), and rejects symlink directories/files. Tree indexing does not replay lifecycle payloads; only selected rows/tree nodes do, with a bounded stat-keyed evidence cache and freshness checked on every read. Tree enrichment includes at most 10,000 discovered sessions and uses existing depth/cycle protection. These conservative caps can omit older sessions; they never establish completion or release ownership.
- **Residual MCP identity limitation requiring root decision:** `claude.ts` binds tool specs to `() => trackingId`. `toolAdapter.ts` creates an MCP server per socket connection; `mcp-server-shim.ts` relays bytes without authenticated caller-thread context. Native children inherit the same `mcp_servers` socket configuration. Neither connection order, extra connections, nor model-supplied arguments prove child identity. This patch labels the root scope in tool descriptions and the read-only child UI; it does NOT enforce isolation of inherited implicit-current-chat tool calls. A native child can still affect its owning root's title/status/objective/callback identity through those tools. Enforcing isolation with this transport would require disabling identity-sensitive tools for the root as well, or a separately verified child-scoped transport/configuration mechanism. Spawning remains enabled. This is intentionally reported rather than falsely advertised as child-local management.
